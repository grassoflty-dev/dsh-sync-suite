## 10 2026-11-28 上午追加的硬事实（读交接时连同上文一起读；上文若与此节冲突，以此节为准）

1. **执行子代理一旦 inactive 就无法续用。** 给已结束或正忙的子代理发消息，返回的是 `Error: subagent "<name>" is unavailable`；**这个报错不是「死没死」的判据**——正忙的车道也会这样报。所以一条车道静默下来只能**整条重派**，不能「续聊」补救。这就是 `docs/MODULES.md` §0.1 第 6 条存在的理由。

3. **定时任务按设备独立**：DSH 自己的任务住在 DSH 自己的调度器里（桌面可见；平板经远程控制看到，因为远程控制就是桌面页面），平板上的任务只属于那台平板。两者**都不进仓库、不做 git 同步**，也**不随重装保留**（应用私有存储随卸载清空，没有找到可持久的替代存放点——这一条如实写在这里，交由用户决定）。
4. **插件日历工具改名 `timeline_*` 是「计划中」，不是「忘了」**：模块 id `mod-plugin-timeline-tool-rename`，动机是不要与 DSH 宿主设备本地的 `schedule_*` 同名。它需要一次插件构建，`dist` 冻结期间**故意不做**。
5. **三条「把工具瞬态当成工作状态」的教训**（今晚各发生一次，同一类错误换三种外衣）：
   (a) 一个 park 副本差一点把已提交的模块**回退**掉；

因此不会推进 `dotsRefreshTick` / `cloudChatRefreshTick`。回到 Home 时 `Home.ets:251-259` 的 `onPageShow`
只推进 `scheduleShowTick` / `instancesShowTick`；`homeStartupSync.request()` 冷启动后已经用掉；
`maybeForegroundSync()` 又被 5 分钟冷却（`model/syncTriggerPolicy.ts` 的 `FOREGROUND_MIN_AGE_MS`）挡住。
⇒ 存在「同步已完成、回到首页、当前分段仍是空态」的可达状态。空态文案因此**不能**写「回到本页即可看到」，
也**不能**写「最近一次」——这正是本模块先把第三句收紧成「本页显示最近一次同步的结果」、最终定为
「**本页显示上次读取到的同步结果**」的原因（演进见 §13.3）。

**修法**：`Home.onPageShow` 同时推进两个 chat tick（只重读本地索引，不跑网络、不跑第二个周期）；
配套 retarget `homeGlobalRefresh` / `structureGuards` 里钉 `onPageShow` 与 pane props 的断言；
**新增一条测试：在冷却窗口内返回首页后，面板不得停留在陈旧状态**（构造「周期已完成 + 冷却中 + 返回」三条件）。
做完之后「回到本页即可看到」会在所有可达路径上为真，届时可以再讨论是否把面板文案恢复成与页面逐字一致。

### 13.8 这一轮的教训（写入 docs 批次的「方法」一节，别只是记在这里）

- 这个缺陷是**设备 pass 发现的，不是测试套件发现的**：两个面板各自都有 per-file 锚点（`paneLayout` / `shellLayout`
  钉着它们的旧文案），所以套件全绿而产品是错的。今晚这是**第二次**出现「测试形状的守卫全绿、产品行为是错的」。
- 判断一条守卫有没有用，不看它存在，看它**表达的是不是那条规则**：「空态必须经 `EmptyState`」是一条规则；
  「`CLOUD_REPO_SETUP` 这个字面量还在」只是那条规则留下的**化石**——化石还在，规则可能已经死了。
