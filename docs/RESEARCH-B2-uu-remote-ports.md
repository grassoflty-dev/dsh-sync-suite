## 0. 结论

**一句话：网易 UU 远程**确实有**端口映射 / 内网穿透**（官方称「隧道穿透能力」，2026-05 上线，免费内置），用户是对的、上一轮是错的；但它给的是「**主控端本地端口 → 远端服务**」的 `ssh -L` 式本地端口转发，出口是 `127.0.0.1:本地端口`，**不是公网 URL/域名**，且**主控端只支持 Windows / macOS 电脑**——所以它能满足「笔记本在外访问家里 PC 的 40596」，**不能满足「平板在任何网络下打开 `http://host:port/?token=`」**。**

**置信度：强（高）**
- 「功能存在」= 强：官方帮助中心专文 + 官方 blog 上线公告 + 2 篇带截图的第三方实测 + 1 个把该功能做成 CLI 的开源项目，四类来源互相独立且一致。
- 「形态是本地端口转发而非公网 URL」= 强：四类来源对「访问 `127.0.0.1:本地端口`」表述完全一致，无一处提到公网地址或域名。
- 「平板不能做主控端」= 中偏强：官方文档明写「主控端和被控端均仅支持 Windows、macOS 电脑端」，开源项目作者实测补一句「手机不能当发起方」；但官方同时说「更多平台和协议支持持续开发中」，属**当前不支持、未来可能变**。

**与上一轮的差异（关键）**：上一轮 `RESEARCH-B-uu-remote.md` §0 判定「UU 远程不能当隧道用——官方功能集里根本没有端口转发、内网穿透、虚拟局域网」，**这条判定是错的，必须撤回**。正确表述是：功能有、且是真隧道（已实测可跑 SSH / MySQL / Nacos / HTTP 页面），但**隧道两端都必须是电脑**，所以对「平板」这个具体目标仍不可用——结论从「没有这个功能」改成「有，但形态不对口」。

### 4.2 ★ 对「平板在任何网络下打开 DSH Web GUI」的判定

**不能直接用。** 三道硬门槛，任一道都过不去：

1. **主控端平台限制**（最硬）。A1 原文：「支持设备：**主控端和被控端均仅支持 Windows、macOS 电脑端**」；A2 注脚「本功能目前支持 **Windows 主控端**」；C1 边界段「**手机不能当发起方**（没有 CLI、没有 shell）」。→ 平板（Android/iOS）**没有「端口映射」入口**，无法在自己身上开一个本地端口。
2. **出口是主控端的回环地址**。即使平板能发起，隧道出口也是**主控端那台机器**的 `127.0.0.1`，不是「一个可从任意网络访问的 URL」。要变成 URL，还得在主机侧再做一层 `0.0.0.0` 监听或反代——而 DSH 默认只听 `127.0.0.1`。
3. **无公网地址/域名出口**。目标形态「平板浏览器或 WebView 直接打开 `https://xxx` / `http://host:port/?token=`」在这套机制里不存在。

**能成立的变体（供用户决策，非本任务目标）**：
- **笔记本 → 家里 PC**：笔记本装 Windows/macOS 版 UU 远程 → 建规则 `本地端口 40596 → 127.0.0.1:40596` → 笔记本浏览器开 `http://127.0.0.1:40596/?token=…`。**这条路是通的**，WebSocket 也能走同一条 TCP。C1 已实测到 44–56 ms 境内延迟，体验优于走境外中继的 Tailscale（同环境实测超时）。缺点是每次要开 UU 客户端 + 建会话（可用 C1 的 `watch` 式常驻看护缓解）。
- **平板 → 家里 PC**：只能回到「远控看屏幕」（UU 远程的手机/平板端远控是支持的），即上一轮说的降级方案，不是隧道。

> 一句话对比：**UU 端口映射是「有隧道、没 URL、且隧道口只能开在电脑上」**。用户想要的「平板免客户端 + 一个 URL」它给不了；但如果接受「一台电脑常驻做主控端」，它是目前实测延迟最好的境内 TCP 隧道之一。

### 6.3 方法论教训（比结论更重要）

1. **「官网导航 + 帮助索引」是弱取证面**。官方 CMS 常把新功能文档做成孤儿页（有 URL、无入口）。必须补：blog 全量标题、`site:` 检索、`sitemap`。

4. **不要用品类推断替代逐产品查证**。上一轮「远控类一律不能当隧道」是最严重的错误来源——它让调研者在没查的情况下就写下了结论。
