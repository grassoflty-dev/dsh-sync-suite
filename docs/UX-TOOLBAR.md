# 手写板工具条两行时的行分配（B 批便捷性 · 2026-11-18）

> 结论来源：`entry/src/harmony/ets/pages/Handwriting.ets` 的 `topBar()`（第 2025–2077 行）。
> 本页只描述**行分配定版**与判定口径；工具条整体定版见 [UI-DESIGN.md §9](UI-DESIGN.md)。

## 1. 两行分支的行分配表（`topBarTwoRows()` 为真时）

| 行 | 控件（源码顺序） | 个数 | 语义 |
| --- | --- | --- | --- |
| 第 1 行 | `‹` 退出 · 笔迹 · 橡皮 · 手动框 · 插入 ▾ · `↶` 撤销 · `↷` 重做 | 7 个单元格 | **写字的全流程工具**（画、擦、框、插、后悔） |
| 第 2 行 | 分页组 `[ −|+ ][n/m][‹|› ]` · 完成 | 2 项（分页组渲染成 3 个小格） | 低频的翻页 + 收尾主操作 |

- 第一行依次对应 `CELL_EXIT / CELL_INK / CELL_ERASER / CELL_SELECT / CELL_INSERT / CELL_UNDO / CELL_REDO`；
  第二行是 `pageStepper()` 后跟 `CELL_FINISH`。
- 两行总高仍是 `topBarHeight()` = **2 × `barThickness()`**（不含 1vp 分割线），
  两行都是静态布局：**没有任何横向 Scroll**，控件不压缩、不隐藏（§9.1 / §9.6）。
- 一行分支（`topBar` 的 `else`）仍是同样 9 项、顺序不变：退出/笔迹/橡皮/手动框/插入/撤销/重做/分页组/完成。

## 2. 为什么这么分

1. **高频优先**：笔迹 / 橡皮 / 撤销 是落笔期间每隔几秒就要按一次的键，被挪到第二行等于每次都多一次
   眼手定位；它们必须留在**第一行**。退回 / 插入 / 重做相对低频，但也留在第一行避免换行找键。
2. **第二行只放「低频 + 收尾」**：翻页是整页粒度的操作，完成是一次性动作，放第二行不伤效率；
   同时把分页组的三个 44vp 小格与 64vp 的「完成」单独排一行，才放得下（真机 673.7vp 竖屏实测）。
3. **绝不横向滚动**：横向 `Scroll` 会把橡皮/撤销滚出屏幕并抢走点击手势（§9.1 / §9.2 的两个 P0 成因）。
   两行是「不滚动」的下限实现，因此不允许用「压缩分页格到 < 44vp」来换一行。

## 3. 这条结论怎么被钉住（静态断言，不依赖真机）

`apps/arkui-schedule/tools/test/handwritingToolbar.test.mjs` 的
`缺陷 3` describe 内有一条独立用例：

`两行分支第一行必须含高频三项（笔迹/橡皮/撤销），第二行只放分页组 + 完成`

它按 `Row({ space: this.controlGap() })` 把 `topBar` 的两行分支切成 `rows[0] / rows[1]`，钉住 4 条不变量：

1. `rows[0]` 的 `buttonCell` 序列**逐项等于** 退出/笔迹/橡皮/手动框/插入/撤销/重做（含高频三项，各 1 次）；
2. `rows[1]` **不含** 笔迹/橡皮/撤销（`CELL_INK / CELL_ERASER / CELL_UNDO` 出现次数 = 0），
   只允许 `CELL_FINISH`，且「完成」排在 `pageStepper()` 之后；
3. 两行分支里 9 项各出现 **恰好 1 次**、合计 9（防止有人在两行里多塞或漏放一份）；
4. **反向自测**：把 `rows[0]` 的 `CELL_UNDO` 一行用 `.replace()` 删掉（或挪到 `rows[1]`）后重跑判定函数
   必须判红 —— 证明断言不是空转。

**边界（这条断言覆盖不到什么）**：
- 真机手势：手指/手写笔点击是否命中、`onClick` 是否被父容器手势吃掉；
- 实际像素宽度：`topBarRequiredWidth()` 的数值自证在测试里是用公式算的，真机 density / 视口宽
  仍要靠 `onAreaChange` 实测；折行与否的**真机渲染**结果不由本断言保证；
- 视觉（间距、分割线、深色主题下的对比度）与横屏 rail 不在本页范围。
- **本轮是静态断言，不依赖真机：`hdc list targets` 未跑，真机未接。**
