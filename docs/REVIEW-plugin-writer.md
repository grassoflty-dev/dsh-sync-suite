# Plugin writer review — mod-plugin-git-store (writer + cycle + migration)

## Verdict

**FAIL** — the migration abort itself is airtight at function level (M02/M03 prove it), but a malformed outbox upsert can be written as an empty `records.json` and pushed, and none of the writer/cycle/migration entry points is reachable from production code; I would not merge this half as-is. Major findings remaining: 7 (1 Blocker + 6 Major).

The one-sentence reason is deliberately narrow: **this is not a failure of the migration algorithm** (`packages/dsh-dots/src/sync/repoPath.ts:170-186` is fail-closed for the dangerous case, and `test/plugin-v2-migration.test.mjs:70-111` proves the legacy dir, its extra commit and its bytes survive) — it is a *write-layer* data-destruction path plus zero production integration.

## Findings

### Blocker

- **[B1] `packages/dsh-dots/src/sync/cycle.ts:326`, `:382-390`, `:374`, `:500-503` — a shape-invalid outbox `upsert` is applied, serialised to the empty string, atomically written and pushed, and the intent is dequeued as "applied".** `parseRecordLine` only checks "is a JSON object" (`cycle.ts:382-390`); no `isValidTsShape` / `planUpsert` / `normalizeForWrite` is applied to replayed intents. `recordsTextOf` delegates to `buildRecordsText`, whose self-check returns `''` on any invalid record or media field (`packages/dsh-dots/src/timeline/records.ts:290-313`, validation at `:318-385`), but `unionDay` does **not** check the `''` sentinel (`cycle.ts:374-375`), unlike the direct-write path `planUpsert` which does (`packages/dsh-dots/src/timeline/write.ts:356-358`). `runV2Cycle` then writes it (`cycle.ts:500-503`) and commits/pushes it (`cycle.ts:548-560`); `dayIntegrityError` skips empty text (`cycle.ts:401-413`), so the next cycle accepts the blank file as valid. Reproduced against committed `dist`: an intent with `title:123` yields `unionDay(...).recordsText === ""` and `applied: [intentId]`. The app reference rejects exactly this case with typed `E_TS_SHAPE` before touching the union (`apps/arkui-schedule/entry/src/main/ets/model/syncProtocol.ts:690-707`, via `normalizeForWrite` at `:307-329`). No test feeds a malformed intent line. **Required fix:** validate every replayed upsert through `planUpsert`/`isValidTsShape` (drop to `dropped` with typed reason), and refuse to write when `recordsText === ''` (`E_CORRUPT`, zero writes, intent retained).

### Major

- **[M1] `packages/dsh-dots/src/sync/cycle.ts:433`, `repoPath.ts:149`, `gitPort.ts:41`, `repoPath.ts:41` — none of the four new entry points has a production caller.** A repo-wide symbol search finds `runV2Cycle`, `migrateLegacyWorkDir`, `GitRepoV2Port` and `resolveV2RepoDir` only in `test/plugin-v2-*.test.mjs` and their compiled `dist/sync/*.js`; `src/index.ts`, `src/rpc.ts` and `src/schedule/**` never import them. The abort path is proven in isolation but **never runs for a real first-run user**, so the "one place users can lose commits" (`docs/PLUGIN-GAPS.md:35`) is still unprotected end-to-end. **Required fix:** either wire migration + cycle into the plugin's startup/write path in this module, or state in code/docs that this is an unwired library and block the "unprotected upgrade" scenario explicitly.

- **[M2] `packages/dsh-dots/src/sync/cycle.ts:91-95`, `:435`, `:558`, `:564` — outbox persistence is in-memory in tests only; no file-backed `OutboxPort` exists anywhere in `src/`.** `CycleOptions.outbox` is an injected interface (`cycle.ts:111-119`); the only implementations are `MemOutbox` (`test/plugin-v2-cycle.test.mjs:88-92`) and a second in-file fake. Contract §13 requires a repo-external `%USERPROFILE%\.dsh\dots\outbox\<repoHash>.json` with atomic replace and cross-session `attempts` (`docs/DATA-CONTRACT-v2.md:210-225`); none of that is implemented, so `maxAttempts=4` "cross-session, never reset" is unproven (C10 at `test/plugin-v2-cycle.test.mjs:219-236` only reuses one JS object). **Required fix:** add a real `NodeOutboxPort` (repo-external path, atomic tmp+readback+rename) and a restart-persistence test; until then list attempts persistence as `unverified`.

- **[M3] `packages/dsh-dots/src/sync/cycle.ts:548-560` + `:194-199`, `:462-463` — a rejected push leaves a local unpushed commit, so every subsequent cycle fails `HEAD == origin/main` with `E_NOT_SYNCED` and zero writes; there is no in-module recovery.** Hard requirement (b) forbids the contract's `git reset --hard origin/main` (`docs/DATA-CONTRACT-v2.md:205,255`), and the module correctly omits it — but it also offers no alternative recovery (no park-and-rebase, no user-facing "manual reconcile" transition). The outbox intents keep their attempts but can never be replayed because the gate short-circuits at `cycle.ts:463`. This is a permanent read-only wedge after the first real non-fast-forward. **Required fix:** document and implement a safe recovery path (e.g. typed `E_LOCAL_PENDING` with an explicit, user-confirmed local-commit handoff), or at minimum a typed, visible dead-end state; add a second-cycle test after push rejection.

- **[M4] `packages/dsh-dots/src/sync/cycle.ts:259-265`, `:375` — conflict audit rows are appended in `ids`-Set insertion order; the app sorts them deterministically.** App reference sorts by `(ts, id, dedupeKey)` UTF-8 bytes before returning (`apps/arkui-schedule/entry/src/main/ets/model/syncProtocol.ts:769-784`); the plugin returns `conflictRows` unsorted. With two+ same-`(id,ts)` conflicts from different ids, swapping remote/local can produce different `conflicts.jsonl` byte order on two devices. C07 (`test/plugin-v2-cycle.test.mjs:176-191`) asserts order-independence with **one** conflict row only, so it cannot catch this. **Required fix:** port the app's deterministic sort and add a multi-conflict swapped-sides test.

- **[M5] `packages/dsh-dots/src/sync/repoPath.ts:188-195`, `:166-168` — the "target exists" re-point path writes the migration marker without verifying that `targetDir` is the same repo/remote as `legacyDir`, and the marker then makes migration a permanent no-op.** `markerTargets` compares only the target path (`repoPath.ts:130-140`); no `origin` URL, HEAD or `.git` identity of the target is checked. If the app's `git-repo/` is stale or belongs to another remote, the plugin is permanently pointed at the wrong clone while the legacy directory (possibly with commits) is left as "operational residue". M05 (`test/plugin-v2-migration.test.mjs:137-152`) only asserts the marker bytes and that the legacy dir survives; it does not assert target identity. **Required fix:** verify target remote URL/HEAD against the legacy repo before writing the marker; fail typed and touch nothing on mismatch.

- **[M6] `test/plugin-v2-cycle.test.mjs:296-316` — the two source-shape guards do not scan what they claim.** `\breset\b` (`:304`) does **not** match camelCase `resetHard` / `resetToOrigin` (verified with the exact regex: `resetHard → false`), and C16 reads **only** `dist/sync/cycle.js` (`:313`), not `dist/sync/gitPort.js` or `dist/sync/repoPath.js`, so a regression in the compiled git port's history-rewrite surface is invisible. Positive assertion `/force: false/` (`:315`) proves only that `PUSH_ARGS` exists in `cycle.js`, not that `gitPort.ts:100-106` still enforces it at execution time. **Required fix:** broaden the regex to `resetHard|reset[A-Z]|\breset\b|rebase|checkout|--force|force\s*:\s*true`, scan all four source files **and** all three compiled `dist/sync/*.js`, and assert the compiled push guard too.

### Minor

- **[m1] `packages/dsh-dots/src/sync/cycle.ts:394-398` — `decidedAtOf` falls back to the injected `now` for an unparseable ts; the app returns the input ts unchanged (`apps/arkui-schedule/entry/src/main/ets/model/syncProtocol.ts:294-300`).** Deterministic per run but a byte-level divergence on corrupt input; use the app's fallback.

- **[m2] `packages/dsh-dots/src/timeline/write.ts:264-273` — `deletedLedgerLine` / `restoredLedgerLine` build bytes with ad-hoc `JSON.stringify`, not via `src/timeline/records.ts`.** Decision ② (`docs/PLUGIN-GAPS.md:34`) is about record bytes and is honoured for records, but these are a second encoder surface for ledger bytes; consider moving them into the canonical serialiser so a future key-order fix flows through.

- **[m3] `packages/dsh-dots/src/sync/repoPath.ts:170-181` — fail-closed is conditional on HEAD resolving.** With `origin/main` missing but HEAD present, `unpushed = 1` (`:178-180`) — the report's claim is correct for that case. If HEAD is also unresolvable (corrupt repo / transient git failure; `gitRead` returns `''` on any non-zero exit at `:111`), `unpushed` stays `0` and the directory is moved. No bytes are destroyed by `rename`, but the claimed "unresolvable ⇒ 1" is not literal. Add a M-test for the HEAD-unresolvable case and consider treating it as `E_LEGACY_UNPUSHED`.

- **[m4] `packages/dsh-dots/src/engine/git.ts:393-401`, `:485-486` — `fetchMain()` (`packages/dsh-dots/src/sync/gitPort.ts:67-69`) can write `.git/config` via `ensureRemote()` before the full `HEAD == origin/main` gate.** Not a `timeline/**` write and not a history rewrite, but it is a write before the full gate; document the exception or use a read-only fetch port.

- **[m5] `packages/dsh-dots/src/sync/cycle.ts:485-491` — `writtenPaths.push(SCHEMA_MARKER_PATH)` is unconditional in the `needSchema` branch.** If another process created the marker between the two reads (`:438` and `:486`), no write occurs but the path is staged/committed-reported and `attempts` becomes 1; make the push conditional on the actual `atomicReplace` result.

- **[m6] `packages/dsh-dots/src/sync/cycle.ts:98-109`, `:149-159` — the `syncing` state is declared and treated as replayable but never assigned; `markAttempt` only produces `pending`/`failed`.** Contract §13 lists `pending / syncing / failed` (`docs/DATA-CONTRACT-v2.md:223`); the middle state is untested and unproven.

- **[m7] `packages/dsh-dots/src/sync/cycle.ts:229-236` and `apps/arkui-schedule/entry/src/main/ets/model/syncProtocol.ts:443-453` — both sides discard `parsed.resolutions`, so equal-`ts` losers already present inside a single `records.json` are never appended to `conflicts.jsonl`, despite contract §4 line 99 requiring union write stage to preserve them.** Parity between the two implementations is intact; the shared contract gap should be clarified rather than "fixed" in one lane only.

### Nit

- **[N1] `packages/dsh-dots/src/sync/cycle.ts:100`, `:306` — intent op is named `purge`; contract §13 calls it `purgeRows` (`docs/DATA-CONTRACT-v2.md:223`).** Semantics match; align the spelling to avoid cross-device/version confusion.

- **[N2] `packages/dsh-dots/src/sync/gitPort.ts:100-106` — the runtime `force:false` assertion has no direct unit test** (C16 only inspects compiled `cycle.js`); add one when fixing M6.

## Residual risk & unverified

- **Real remote auth / push:** no network test; `GitRepoV2Port` never exercised against a真实的 Gitee/GitHub endpoint; token hygiene inherited from `engine/git.ts:276-315` but unverified here.
- **Real two-device union:** C07/C08 compare plugin to plugin and a hard-coded expectation, not to the app's compiled `unionDay`; the app's deterministic conflict sort (M4) and shape-gate (B1) diverge.
- **Outbox persistence / attempts across restarts:** no file-backed port exists (M2); `syncing` state unused (m6).
- **Live DSH session:** plugin not installed on any device; no on-device verification; `src/index.ts`/`rpc.ts` never load this half (M1).
- **App lock contention on the shared clone:** plugin and ArkTS app may write the same `git-repo/` concurrently; no lock, no test, no documented arbitration.
- **Migration end-to-end:** abort proven only as a function; no production first-run call (M1), target identity unchecked (M5), HEAD-unresolvable edge fail-open-ish (m3).
- **Post-push wedge:** after a rejected push, local commit + strict gate = permanent `E_NOT_SYNCED` (M3).
- **Data loss via malformed intent:** confirmed empty `records.json` write path (B1), untested.
- **Guard durability:** C15/C16 miss camelCase and compiled git-port regressions (M6).
- **Injected path assumption:** `appFilesDir` and `overrideDir` are never reconciled with `GitSyncService.getRepoRoot()` at runtime (check 9).
