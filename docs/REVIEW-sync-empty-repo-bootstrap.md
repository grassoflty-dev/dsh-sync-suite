# Review — mod-sync-empty-repo-bootstrap

Scope: 7 in-scope working-tree files on `main` @ `7b109938b8ae469c1bb699a00d18d77879b31eda`, reviewed read-only (no build, no tests, no git write operations, no subagents). Only this file was created.

## Verdict
CONDITIONAL PASS — The three-state split, pre-fetch probe, no-force/no-rewrite discipline and typed no-main refusal are basically sound and compile-verified, but three Majors remain open (tags-only remotes are misclassified as empty, probe transport/auth failures escape the typed-outcome path, and the bootstrap write path drops the §11 schema gate) and must be fixed before release.

## Findings

### Blocker
None. (No path in the reviewed code deletes remote history or force-pushes; the two fail-open risks are classified Majors below because they create a branch rather than overwrite existing objects, and one is a narrow ref-layout edge case.)

### Major
- [M1] `apps/arkui-schedule/entry/src/main/resources/rawfile/git/git-bridge.js:2057-2063` — `isEmpty` is computed from `info.refs.heads` **only**. The bundled `getRemoteInfo` (`isomorphic-git.js:8`, `getRemoteInfo:wn`) also returns `refs.tags` (and `refs/pull`); its nested result puts tags under `info.refs.tags`, not `heads`. A remote that has tags but no branches yields `hasMain=false, isEmpty=true`, so `remoteStateDecision` returns `bootstrap` and a root commit is pushed — exactly the "non-empty remote lacking main" case the safety floor says must keep a typed error and never be bootstrapped. This also contradicts the declared contract of `RemoteLayout.isEmpty` at `syncCycle.ts:43` ("没有任何 heads/tags 引用"). Fix: compute emptiness across **all** ref categories returned by `getRemoteInfo` (heads ∪ tags ∪ any other `refs.*` keys), and add a fake-port case with a tags-only remote asserting `E_GIT` / no commit / no push.
- [M2] `apps/arkui-schedule/entry/src/main/ets/services/gitRunner.ets:139` — `await v2Git('remoteLayout', ...)` sits **outside** the `try` (which starts at line 140/156 and only guards `JSON.parse`). `GitSyncService.v2Git` rejects with a `SyncError` carrying the bridge's `E_AUTH`/`E_IO`/timeout code (`GitSyncService.ets:1296,1334,2266`), and `runCyclePure` calls `await port.remoteLayout()` with no `try/catch` (`syncCycle.ts:500-501`) — unlike `fetchMain()`, which is caught into `pullFailureOutcome` at `syncCycle.ts:511-517`. `syncProtocolStore.runWiredCycle` (`syncProtocolStore.ets:282-292`) rethrows it as `new Error(text)`, so a network/auth failure on the very first call produces an unhandled rejection instead of a typed tri-state outcome; outbox attempts are not bumped and the status line is not updated. It is fail-closed (no bootstrap), so not a Blocker, but it is a real regression relative to the fetch path. Fix: wrap the probe in `try/catch` inside `runCyclePure` and return a typed outcome (`E_PULL_FAILED`/preserved `E_AUTH`/`E_IO`) after `persistOutbox`, while keeping the fail-closed rule that no exception may map to `isEmpty:true`.
- [M3] `apps/arkui-schedule/entry/src/main/ets/model/syncCycle.ts:405-441` — the bootstrap write path checks only `branchName() === 'main'` (405-408), then calls `write.writeDay` (423-427), `addPaths`/`commit`/`pushMain` (456-459) without ever reading `timeline/schema.json` or calling `assertWritable`. §11 (`DATA-CONTRACT-v2.md:287-288,307`) requires the schema check before **any** `timeline/**` write and the "改 schemaVersion 为 99 → 每条写路径零写入" test. The comment at `syncCycle.ts:389` calls this the "唯一一处" gate exception, but the implementation drops the schema half too. With an unknown-version local `schema.json` on an empty remote, the bad schema is written and pushed before the resumed cycle's gate (`syncCycle.ts:479 → 518`) finally rejects it, publishing a repository that bricks sync on every device. Fix: parse the local schema marker before stage 1 and return `gateFailure({ ok:false, code:'E_SCHEMA_UNKNOWN' })` unless version===2; exempt only the impossible `HEAD == origin/main` assertion.

### Minor
- [m1] `apps/arkui-schedule/tools/test/syncEmptyBootstrap.test.mjs:152-157,302-325` — the "no duplicate root commit after a failed push retry" claim (`syncCycle.ts:394-395`) depends on the bridge swallowing `NothingToCommit` (`git-bridge.js:1539-1545,2140-2145`), but the fake `commit()` unconditionally increments `commitCount` and changes HEAD, and tests 7/7b use `pushFailures: 99` with no recovery run. The retry-after-partial-failure path is therefore unverified by tests and the fake diverges from real bridge behaviour. Fix: add a `pushFailures: 1` case that reruns and asserts one commit, eventual `ok`, and `hasMain === true`.
- [m2] `apps/arkui-schedule/entry/src/main/ets/model/syncCycle.ts:511-517` — the new `E_PULL_FAILED` fetch `try/catch` applies to **all** ports, including old ports that do not expose `remoteLayout()`; previously a fetch rejection propagated. This is a benign improvement but contradicts the "普通周期一字未改 / normal path unchanged" claims in `docs/MODULES.md:169,272` and `docs/ROADMAP.md:671`. Fix: document the new typed code, or scope it to the bootstrapping port.
- [m3] `apps/arkui-schedule/entry/src/main/ets/model/syncCycle.ts:429-440` with `apps/arkui-schedule/tools/test/syncEmptyBootstrap.test.mjs:188-192` — when the port lacks `localTimelinePaths()`, `derived` includes a path only when union content is non-empty, while `writeDay` writes files (including empty `deleted.jsonl`/`restore.jsonl`) unconditionally, so the committed tree can differ from the written working copy. The fake `WritePort` also ignores `texts.conflicts` entirely, so `conflicts.jsonl` handling on the bootstrap path is untested. The production bridge is safer (`listFilesRecursive` at `git-bridge.js:2070`, whitelist at `git-bridge.js:2127-2133`), so this is a fallback/test-fidelity gap, not a production hole.

### Nit
- [N1] `apps/arkui-schedule/entry/src/main/ets/model/syncCycle.ts:60-61` — `E_REMOTE_EMPTY_CODE` / `E_REMOTE_EMPTY_MESSAGE` are exported but never attached to any `CycleOutcome`; they appear only in test 1 (`syncEmptyBootstrap.test.mjs:221-222`). The docs' "空远端 = E_REMOTE_EMPTY 正常起点" is a conceptual label, not an observable result code; the comment at `syncCycle.ts:59` acknowledges this, but the doc wording could mislead.
- [N2] `docs/UI-DESIGN.md` — the only hunk touching this file in `git diff` is the `mod-pane-header-nav-dedupe` entry; there is no `mod-sync-empty-repo-bootstrap` claim there, and the module row itself lists only `docs/{MODULES,ROADMAP}.md` (`docs/MODULES.md:169`). The brief's "three shared doc edits" therefore overstates this module's doc footprint. No incorrect bootstrap claim results.

## Checklist results

1. **State detection correctness — CONCERN.** `remoteStateDecision` (`syncCycle.ts:52-57`) is mutually exclusive/exhaustive and `hasMain=true` always wins (test 1, `test.mjs:216-220`). Probe is at `syncCycle.ts:500` vs `fetchMain()` at `syncCycle.ts:511`, so an empty remote never hits the raw fetch error (test 11, `test.mjs:379-391`). A transport/auth failure cannot be misclassified as empty (bridge throws → `gitRunner.ets:139` throws outside the parse-only `try`), but it escapes as an unhandled error [M2], and tags-only remotes are misclassified as empty [M1].
2. **Safety floor — CONCERN.** Master/unrelated-history case: `git-bridge.js:2061-2062` → `remoteStateDecision(false,false)` → `noMainOutcome` (`syncCycle.ts:363-372`), code `E_GIT` (`syncCycle.ts:66`), English text "Could not find origin/main." plus Chinese next step (`syncCycle.ts:67-69`); test 4 (`test.mjs:260-272`) asserts zero commit/push. JSON parse failure is fail-closed: `gitRunner.ets:141-149` returns `{hasMain:false, isEmpty:false}` → `no-main`, never bootstrap. **But** tags-only remotes break the floor [M1].
3. **Gate exception — CONCERN.** Branch check `syncCycle.ts:405-408`, remote-proven-empty from the probe `syncCycle.ts:500-503`, and the resumed cycle does run the full gate (`syncCycle.ts:479 → 518-521`, `gateOf` at `335-350`). Substitute checks are insufficient because the schema-version half of §11 was silently dropped [M3].
4. **Initial commit content — CONCERN.** Paths come from `localTimelinePaths()` (`syncCycle.ts:445-449`) or the `derived` union path (`429-440`), always with `timeline/schema.json` prepended (`450-452`); the production enumerator `listFilesRecursive(timelineDir,'timeline')` (`git-bridge.js:2067-2070`) returns posix `timeline/**` paths and `addCommit` enforces the whitelist (`git-bridge.js:2127-2133`); deleted/restore/conflicts are included when non-empty (`syncCycle.ts:432-440`). No prefix enforcement inside `syncCycle.ts` itself and the no-port fallback can omit written files [m3]. Fake push copies all `timeline/**` files (`test.mjs:167-169`), so the "本地记录进初始提交" assertion (test 6, `test.mjs:289-300`) is real.
5. **Idempotency — CONCERN.** Second run: push sets `hasMain=true` (`test.mjs:165`), probe returns `normal`, no second commit (`test.mjs:245-258`). Mid-way push-failure retry relies on an untested bridge no-op [m1]; no duplicate root commit in that path is plausible but not proven by the suite.
6. **No history rewriting — PASS.** `bootstrapEmptyRemote` (`syncCycle.ts:397-482`) uses only `addPaths`/`commit`/`pushMain`/`fetchMain`; no `--force`, rebase, `reset --hard`, or `devices/**` in the new code. Bridge push keeps `force: false` (`git-bridge.js:2152`, present in the HAP copy), and static test 10 (`test.mjs:350-377`) pins this.
7. **Outbox semantics on bootstrap push failure — PASS.** `typedPushError` preserves `E_IO`/`E_AUTH` (`syncCycle.ts:462`, helper `256-268`), `bumpAttempts` accumulates the budget (`syncCycle.ts:463`, `syncProtocol.ts:343-346` → `failed` at MAX), `persistOutbox` writes immediately (`syncCycle.ts:464`), outcome is `ok:false` with `bootstrapped:true` and no "已同步" (`syncCycle.ts:465-472`). `attempts: 1` is truthful (one push attempt this cycle); `pending` uses `replayable(parked)` and `failed` uses `countFailed(parked)`, so neither lies. Test 7/7b (`test.mjs:302-325`) confirm typed code, `attempts:1`, and terminal `failed`.
8. **Types / ArkTS soundness — PASS.** Optional members (`syncCycle.ts:128-131,158,496`; `gitRunner.ets:137-161`), imports all used, `JSON.parse(raw) as RemoteLayout`/`as string[]` (`gitRunner.ets:141,126,157`) match existing patterns (`GitSyncService.ets:1316`), `error instanceof Error ? error.message : String(error)` matches existing code (`syncCycle.ts:461,514` and pre-existing `528,650`), `Record<string,string>` and `gateFailure({ok,code:'E_BRANCH_MISMATCH',...})` (`syncCycle.ts:407`) are valid `WriteGateResult` literals (`syncProtocol.ts:58-62`).
